# compleksity

i'm a developer who mostly just likes making things and seeing how far i can take an idea.

i work with a bunch of different stuff depending on what i'm working on. most of the time it's web development, python, javascript, linux, or unity. i also mess around with pc hardware, game-related projects, userscripts, automation, and pretty much anything else that looks interesting.

i don't really like sticking to one specific type of project. i'll make a website one day, a python tool the next, then spend a few hours messing around with linux or trying to figure out how something works.

a lot of my projects start from random ideas. sometimes they're actually useful and sometimes they're just things i wanted to make because i thought they would be cool. either way, i usually end up learning something from them.

## my website

this repository is the source for my personal website and portfolio.

the site is meant to be a simple place where i can show what i'm working on without making it feel like a massive corporate portfolio. i wanted it to feel more like me, so the design is heavily inspired by terminals and linux interfaces.

the whole site uses a dark interface, geist mono, small blue accents, thin borders, and a lot of simple spacing. i wanted it to feel clean without having a bunch of unnecessary animations or huge sections everywhere.

the homepage is basically a quick introduction to me, followed by some of the projects i've worked on, the technologies i use, and ways to contact me.

the projects are separated into their own pages instead of putting everything on one massive page. this lets me actually explain what each project is and show more information without making the homepage cluttered.

## projects

one of the things i've worked on is a collection of python projects. these are mostly smaller tools and experiments i've made while learning and messing around with python.

i also have a decode project which is basically a browser-based encoding and cipher toolkit. it supports things like base64, base32, hex, binary, ascii, rot13, rot47, caesar, atbash, morse, a1z26, bacon, vigenere, xor, reverse, and other simple encoding methods.

another project is stick with it, a game i'm working on in unity. it's one of the projects where i'm learning by actually building something instead of just following tutorials.

there's also steamrip reripped, which is a userscript project based on the original steamrip reripped project by bepi. i modified it to use geist mono and made some additional changes to the styling, typography, branding, favicon, page titles, and game title formatting.

## my linux setup

i use bazzite gnome as my linux desktop.

my setup is pretty heavily customized. i'm running an nvidia rtx 3060, 32gb of ram, and a 1tb pcie ssd alongside a secondary 256gb lexar ssd.

i use gnome 50.4 with geist mono as my main font. the setup also uses a bunch of gnome extensions including blur my shell, burn my windows, desktop cube, compiz windows effect, compiz magic lamp, dash to dock, rounded window corners, glass widgets, gsconnect, caffeine, and a bunch of smaller utilities.

i added a dedicated bazzite gnome page to the website because it's something i actually spend a lot of time customizing. it shows my hardware, operating system, kernel, desktop environment, themes, font, and extensions.

i like linux because i can actually change things and make the desktop work the way i want instead of just accepting the default setup.

## how i build things

i usually learn by building.

if i want to know how something works, i'll try making it myself and figure out problems as they come up. i'll use documentation, existing projects, github, and other resources when i need them, but i prefer actually getting my hands on the code.

i'm also pretty interested in figuring out why something is broken instead of immediately replacing it. that applies to software, websites, linux setups, pcs, and pretty much everything else i work on.

my code isn't always perfect and some of my projects are definitely more polished than others, but that's part of the point. i'm constantly learning and improving things as i go.
